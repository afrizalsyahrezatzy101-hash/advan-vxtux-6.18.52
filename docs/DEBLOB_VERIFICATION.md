# Deblob verification (strict)

Generated by `donors/verify_deblob2.py`.

The stock ROM ships 31 vendor .ko in /lib/modules. For the
deblob to be real, the VXTux build must produce a module
with the same file name, carrying the same code, so the
loader can insmod it and nothing that bound to the stock
blob breaks.

Three levels, each reported on its own:

1. **NAME** - the build emits a .ko with the stock file name.
2. **API** - that .ko has every symbol the stock .ko had,
   local symbols included. The stock blob's locals are the
   driver's own functions, so a replacement that does not
   have them is not the same code.
3. **DEPS** - it imports nothing the stock one did not, and
   every symbol it does import exists in the built vmlinux
   (167,209 symbols).
