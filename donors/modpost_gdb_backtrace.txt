r11 = 0x7ffff7cf6000 is the Elf64_Ehdr of init/main.o. Verified live in gdb:
    e_ident[EI_CLASS] = 2        (ELFCLASS64)
    e_machine        = 183      (EM_AARCH64)
    e_shoff          = 693240    (0xa93f8)
    e_shnum          = 71

    .symtab           type=2   off=0x000000055978  size=11640 entsz=24
    .rela.text        type=4   off=0x00000005a2e8  size=4824
    .rela.debug_info  type=4   off=0x0000000601f8  size=265776
    -> no 4 GiB bias, no bit-32 corruption, no injected garbage.
       (An earlier hypothesis that section offsets carried a 0x100000000

        flags/8, addr/8, offset/8, size/8. The headers are fine.)

4. ROOT CAUSE — PROVEN
==============================================================
`git diff scripts/mod/modpost.h` shows a local "Bionic <elf.h>"
compatibility shim (65 added lines, pre-existing in the tree, NOT mine):

  +#define ELF_R_SYM(i)     ((i) >> 8)
  +#define ELF_R_TYPE(i)    ((i) & 0xff)
  ...
  +#define ELF64_R_SYM(i)   ELF_R_SYM(i)     <-- 32-bit ARM encoding!
  +#define ELF64_R_TYPE(i)  ELF_R_TYPE(i)
  +#define ELF32_R_SYM(i)   ELF_R_SYM(i)
  (this block is repeated THREE times, at lines ~19, ~46 and ~107)

scripts/mod/elfconfig.h:  #define KERNEL_ELFCLASS ELFCLASS64
so modpost.c resolves ELF_R_SYM -> ELF64_R_SYM -> ((i) >> 8).

CORRECT ELF64 encoding is (i) >> 32.  The >>8 form is the 32-bit ARM
relocation encoding. Mixing them shifts every symbol index by 24 bits.

ARITHMETIC PROOF (ground truth read straight out of the .o files):

  /tmp/t3.o  (3-line x86-64 hello world), .rela.eh_frame:
      r_info = 0x0000000200000002
      r_info >> 32 = 2                  (true r_sym; nsym=4)
      r_info >> 8  = 0x2000000 = 33554432
      modpost printed: OOBRELA r_sym=33554432   -> EXACT MATCH

  init/main.o (EM_AARCH64), .rela.text:
      r_info = 0x000000b400000101
      r_info >> 32 = 0xb4 = 180          (true r_sym; nsym=485)
      r_info >> 8  = 0xb4000001 = 3019898881
      modpost printed: OOBRELA r_sym=3019898881  -> EXACT MATCH
      (r_type low-32 = 0x101 = 257 = R_AARCH64_ABS64, correct)

A standalone probe compiled on the codespace reproduces both numbers
bit-for-bit from the two shift amounts. Root cause is certain.

CONSEQUENCE: r_sym = 3,019,898,881 feeds `tsym = elf->symtab_start + r_sym`
(modpost.c section_rela, ~line 1390). Elf_Sym is 24 bytes, so the pointer
lands ~72 GB past the mmap'd image -> non-canonical -> SIGSEGV on the next
load, which is `mov 0x8(%rbx),%rcx` at read_symbols+3727.

This also explains why the crash is 100% reproducible and
input-independent: every relocation-bearing object is mis-decoded.

==============================================================
6. FIX
==============================================================
In scripts/mod/modpost.h, at ALL THREE shim blocks (lines ~51, ~112,
and wherever ELF64_R_SYM is re-aliased), change:

  -#define ELF64_R_SYM(i)   ELF_R_SYM(i)
  -#define ELF64_R_TYPE(i)  ELF_R_TYPE(i)
  +#define ELF64_R_SYM(i)   ((i) >> 32)
  +#define ELF64_R_TYPE(i)  ((i) & 0xffffffff)

ELF32_R_SYM/ELF32_R_TYPE and the base ELF_R_SYM/ELF_R_TYPE/ELF_ST_* may
stay as-is (they are correct for ELF32 and for the 32-bit ARM case the
shim may still serve). Only the ELF64 family is wrong.

Cleaner alternative if the shim is no longer needed on the build host:
delete the shim entirely and just `#include <elf.h>`, letting glibc's
correct ELF64_R_SYM/ELF64_R_TYPE win.

AFTER FIX, modpost should parse cleanly with no OOBRELA warnings:
    ./scripts/mod/modpost -o /tmp/out.symvers -e ./init/main.o init/version.o init/do_mounts.o

==============================================================
7. HYPOTHESIS LINE
==============================================================
H: modpost SIGSEGVs because the Bionic-compat shim in
   scripts/mod/modpost.h hard-codes ELF64_R_SYM as (i)>>8 — the 32-bit
   ARM relocation encoding — instead of the ELF64-correct (i)>>32. With
   KERNEL_ELFCLASS==ELFCLASS64, modpost.c binds ELF_R_SYM to that broken
   macro, so every ELF64 r_info is mis-decoded and the symbol index comes
   back ~24 bits too large (e.g. 3019898881 instead of 180). That index is
   added to elf->symtab_start, producing a non-canonical address, and the
   next load — `mov 0x8(%rbx),%rcx` in section_rela's loop at
   read_symbols+3727 — traps. Deterministic on every input, not CJK
   injection, not heap corruption.
